# Official Content Distribution Policy

This policy protects official learning content while keeping the software
community-friendly.

## 1. Default Boundary

The source code is open under AGPL. Official learning content is not open under
AGPL unless a specific file states otherwise.

Official content includes:

- official word-card packages;
- sample and demo packages;
- card-production blueprints;
- field standards and scene taxonomies;
- official screenshots, manuals, and product explanation assets.

See `CONTENT_LICENSE.md`.

## 2. Public Repository Rule

The public repository may include:

- small functional test packages;
- limited demo packages;
- schema examples;
- production standards;
- non-sensitive card-production templates;
- sample screenshots and manuals.

The public repository should not include:

- full high-value commercial official decks;
- private source ledgers that contain non-public licensing terms;
- bundled third-party audio without explicit redistribution permission;
- any package that cannot pass source and rights review.

## 3. Release Asset Rule

Release assets may include sample packages and acceptance packages only when
their license and source boundaries are clear.

Each public release should include:

- license files;
- third-party notices;
- schema;
- quick-start guide;
- SHA256 checksum file;
- explicit official/community content boundaries.

## 4. Commercial Distribution

Commercial distribution of official learning content requires separate written
authorization from the project owner.

Commercial authorization can be scoped by:

- package;
- channel;
- territory;
- term;
- allowed reuse;
- attribution requirement.

## 5. Community Boundary

Community packages are not official packages by default. They should be marked
as community content and governed by the creator's declared license.

Official channels should not promote community packages as official unless the
package has passed an explicit official acceptance process.

## 6. Audit Trail

Every official package should keep:

- source ledger;
- reviewer;
- release decision;
- version history;
- checksum;
- license statement.
